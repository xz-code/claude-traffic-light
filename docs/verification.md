# 手工验收清单

自动化能覆盖的部分已经覆盖了（事件映射、聚合、点击判定、窗口跳转、忽略会话）。
剩下这些**必须人来判断**——下面每一条都写清了「怎么做」和「什么算通过」。

## 准备

1. 悬浮窗在跑：`.venv\Scripts\pythonw.exe src\main.py`
2. **开第二个 VSCode 窗口，打开另一个项目**（`文件 > 打开文件夹`，
   或 `Ctrl+K Ctrl+O`）。
   第 3 条测试需要两个窗口——只有一个窗口时「跳到那个窗口」无从谈起，
   这正是第一次测试失败的原因。

> 想手动摆出任意灯态来配合测试，用
> `python tools/simulate.py red|yellow|green|dark`，
> 测跳转用 `python tools/simulate.py redat "<项目目录>"`，
> 完事 `python tools/simulate.py clear`。

## 1. 悬停提示

**准备一条带标题的会话**：对任一项目派一次活。标题优先取 Claude Code 自己
总结的会话名（挂在 transcript 尾部，聊一两轮后才出现），没有才回退到**你打的
第一句提问**——那个只由第一条指令决定，之后再说多少句都不会改。
想验"同项目两行不一样"，就在同一个项目里再开一个会话、派一句不同的话。

> 顺带记录一条新的实测结论：Claude Code 的 AI 标题**中途会变**
> （本机 17 个有过该记录的会话里 7 个变过，见过 `nodemon not recognized` ->
> `nodemon 未找到` 这种连语言都换的）。所以灯牌上的名字**跟着变**是对的，
> 不是 bug。细节见 `docs/hook-findings.md` 的 `ai_title` 一节。

**想不看眼睛就确认名字读到了**，直接翻 session 文件里的两个字段：状态目录是
`%LOCALAPPDATA%\ai-traffic-light\sessions\`，一个会话一个 json。

```bash
python -X utf8 -c "import json,pathlib,os,glob; \
[print(pathlib.Path(p).stem[:8], '| ai_title=', repr(json.load(open(p,encoding='utf-8')).get('ai_title')), \
'| title=', repr(json.load(open(p,encoding='utf-8')).get('title'))) \
for p in glob.glob(os.path.join(os.environ['LOCALAPPDATA'],'ai-traffic-light','sessions','*.json'))]"
```

> `-X utf8` 不能省：Windows 控制台默认按本地代码页解释，中文会输出成一串 `���`。

两个字段的**含义不同，都该在**：`ai_title` 是 Claude Code 的总结，
`title` 是你打的第一句。

- `ai_title` 为空、`title` 有值 —— **正常**。这个会话没有 AI 总结（子 agent 和
  老会话一律如此），灯牌回退到 `title`。
- 两个都空 —— 才是故障：hook 没重装，或者 `transcript` 字段没写进去。

**怎么做**：鼠标移到灯上，**停住约半秒**。**不要点击。**

**通过**：
- 鼠标只是**扫过**灯面时**不弹**；停下约 400ms 后才浮出来
- 浮出一个**深色圆角面板**（近黑底、浅灰字），紧贴在灯的**旁边**，不压住灯
- 一行一个会话：左边 `项目 · 标题`，右边是**带色**的状态词，右边缘**对齐**
- **分隔线横贯整个面板宽度**，不会短一截（宽度是跟着表格自适应的，
  不是写死的字符数——标题放宽到 24 字后，写死的 `━` 会短 86px）
- 颜色跟灯一致：红态红字、绿态绿字、黄态黄字
- 有原因时是**中文**（不是 `Claude needs your permission to use ...` 这种英文长句）
- 红灯底部有 `单击跳到等待中的窗口`；绿灯底部有 `单击确认，绿灯熄灭`
- 同项目开了两个会话时，两行的名字**不一样**
- 只列非暗态会话；超过 6 个时最后一行是 `…还有 N 个`
- **鼠标停住不动，面板不闪烁、不重绘、不跳位；停多久都还在**（没有超时）
- **鼠标从灯移到面板上：面板继续显示，不会消失** ← 本次修的就是这个
- **把灯拖到屏幕右边缘再悬停：面板翻到灯的左侧，不会被挤出屏幕**
- **按住左键拖动灯的时候，面板不出现**（拖完松开、光标还在灯上，约 400ms 后才弹）
- 鼠标移开再移回来，内容与当前灯态一致（不是上一次的残留）
- 顺带看一眼：右键菜单和「安装 hook」对话框外观没变

**不通过**：
- 什么都不弹，或弹出来只有「AI 状态灯」
- **鼠标刚碰到灯就立刻弹**（说明悬停延迟没生效——扫过灯面时也会弹出来）
- **鼠标移到面板上时它消失了**（面板没接上悬停状态）
- **鼠标移到面板上时它跳位或重弹**（那是旧 QToolTip 时代的老毛病，见下）
- **拖动灯的时候面板跟着跑**
- **面板压住了灯**，或者灯贴屏幕边缘时被挤到屏幕外
- 提示里出现英文原文（原因映射没生效——多半是 hook 没重装，见 README 安装一节；
  会话名变成 `#a3f20000` 这种也是同一个原因）
- 同项目的两个会话看起来**逐字相同**
- 面板底色是浅色的（样式表没生效）
- 鼠标停住时面板持续闪烁或重绘
- 提示内容与灯色对不上（灯是绿的、提示说等待）

### 悬停面板为什么是自己画的（别改回 QToolTip）

#### 一、QToolTip 做不到这个需求

需求是"**鼠标移到提示上就一直显示**"。QToolTip 做不到，三条都是实测：

- 它到时限会自己收走，而那个隐藏是 `QTimer::singleShot`——**停不掉**
  （枚举 QTipLabel 的子定时器：0 个）
- 定期用相同文本重调 `showText` 也不重置它的计时（3/6/9 秒都还在，
  **第 10 秒照样消失**）
- 它一旦销毁，下次弹出**必然新建窗口** = 可见的一闪

而且它把提示框放在**光标右下 `(2, 光标高)`**，灯只有 52×140，所以提示框
**必然压住灯**、离光标只有几个像素——鼠标稍微一动就踩上去。踩上去之后，
QTipLabel 自带的**全局**事件过滤器会立刻收走它（这条路径不经过我们的代码），
光标又落回灯上、于是再弹一次，形成"碰到就以光标位置重弹"的死循环。

早先为了压住这个循环，写过一个**按类名找 `QTipLabel`、改它原生窗口属性**
的 hack（`WS_EX_TRANSPARENT`）。换成自己的面板之后，那个 hack 连同它对
Qt 内部类名的依赖**一起删掉了**——这是本次改动最大的意外收获。

#### 二、现在是怎么实现的

`widget.HoverPanel` 是个自己拥有的顶层窗口（`Qt.Tool | 无边框 | 置顶`，
不抢焦点）。因为窗口是我们的：

- 显示 / 隐藏完全由 `TrafficLight` 的两个定时器说了算，没有第二套超时
- 位置自己摆：优先贴灯的**右侧**，右边放不下就翻到**左侧**，最后钳进
  `availableGeometry()`（用 available 而不是 geometry，免得压住任务栏）
- 刷新内容只是 `setText`，**窗口不动**，所以不存在"重弹"
- 面板自己的 `enterEvent` / `leaveEvent` 接到 `_on_hover_enter` /
  `_on_hover_leave`——鼠标从灯挪到面板上时，灯发 `Leave`、面板发 `Enter`，
  净效果仍是"在悬停"，所以面板不会消失

#### 三、灯自己的悬停仍然只发生在不透明像素上

`WA_TranslucentBackground` 下**完全透明的像素是点击穿透的**。所以悬停和点击一样，
只发生在**画了东西**的像素上（外壳 52×140 整块不透明，所以整盏灯都能悬停；
灯的圆角外那一圈透明区域既不能点也不能悬停）。

这一条**只对灯**成立。面板是普通窗口，整块都收鼠标事件——但它圆角外那几个
像素同样是穿透的，只是面积小到感觉不出来。

## 2. 拖动与位置记忆

**怎么做**：
1. 按住灯的外壳（圆角深色区域，任意位置）拖到屏幕另一个角
2. 右键 → 退出
3. 重新启动 `.venv\Scripts\pythonw.exe src\main.py`

**通过**：
- 拖动跟手，不卡顿、不跳变
- 重启后灯**还在你拖到的新位置**，没有回到默认位置

**额外一条**：故意**按住灯珠拖动**（不是外壳），松手后灯应该只是移动了，
**不应该被"确认"掉**（绿灯不该熄灭）。这验证的是 6px 移动阈值。

**不通过**：
- 拖不动
- 重启后回到默认位置（位置没存上）
- 拖到别的显示器后消失或跑到屏幕外（应该会被拉回可见区域）

## 3. 点击跳转（设计重头）

**前提**：两个 VSCode 窗口，各开一个项目。

**怎么做**：
1. 造一盏指向「另一个项目」的红灯：
   ```bash
   python tools/simulate.py redat "<另一个项目的目录>"
   ```
2. 点一下你的 VSCode，让它处于前台
3. 点一下灯的**红色灯珠**（不是外壳）

**通过**：VSCode 切到了那个项目的窗口——就是 `redat` 指定的那个。

**自动判定**（不用肉眼）：
```bash
python tools/test_jump.py "<另一个项目的目录>"
```
它会读前台窗口标题，执行跳转，再读一次，直接告诉你是通过还是失败。
注意它会真的抢一次焦点。

**不通过**：
- 点了没反应
- 切到了错误的窗口
- 新开了一个窗口而不是复用已有的（说明 `code -r` 没匹配上工作区）

> `code` 必须在 PATH 里。装 VSCode 时勾了「添加到 PATH」才有。
> 用 `python tools/test_jump.py list` 能看到当前所有 VSCode 窗口标题，
> 排查"到底切到哪儿去了"很有用。

## 4. 忽略会话（右键）

**为什么有这个**：红态唯一的自动出口是"同一个会话的下一个事件"。一个被丢下的会话
（窗口开着、`claude.exe` 还活着）永远不会有下一个事件，僵尸清理也够不着它——于是
红灯永远闪，并把别的会话的绿/黄一起盖住。右键忽略就是那个人肉出口。

**怎么做**：
1. 造一盏红灯：`python tools/simulate.py redat "<另一个项目目录>"`
2. 再键出第二个会话（可选，用来验证"只影响那一个"）：
   `python tools/simulate.py yellow`
3. 在灯上**右键 → 忽略会话**，点那一项

**通过**：
- 被忽略的会话从 `%LOCALAPPDATA%\ai-traffic-light\sessions` 里消失
- **只有它消失**——其他 `*.json` 还在，内容也没变
- 红灯**立刻**灭（不是 250ms 后），灯回落到那个会话该有的颜色
- 到那个 Claude Code 会话里**再派一次活**，它自动复活成黄；再卡住授权照样变红
- `debug.log` 里有一行 `IGNORE <session_id> by=menu`
  （**只有以 `AI_TRAFFIC_LIGHT_DEBUG=1` 启动悬浮窗才有这一行**——见 README 的排查一节）

**不通过**：
- 点了没反应
- **别的会话也一起消失了**——这是最严重的一条，等于凭空抹掉一次告警
- 被忽略的会话在**没有任何动静**的情况下自己回来了
  （那是 `hook_writer` 里 `path.exists()` 与原子写之间的窄竞态，值得记录下来）

**一条反直觉的、不算故障的**：如果你点了一个**没有 `●` 前缀**的红灯，灯可能仍是红的——
那是**另一个**红灯在占位。先看菜单里谁带 `●`，那才是正在点灯的那个。
同理，一次右键只能忽略一个会话（Qt 在条目触发后就关掉了整条菜单），三个卡死就右键三次。

**另一条不是故障的**：忽略一个**绿**的会话，等于一次"没留下 `acked_by` 记录的确认"。
绿灯本来就要你点确认，这里只是换了种方式让它消失，不会记录在案。

**还有一条不是故障的（标题相关）**：忽略一个会话，等于连它的标题一起删了。
那个会话下次真有动静复活时，标题会变成**让它复活的那条指令**，不是原来那条。
对被丢下又回来的会话来说这反而更准（它描述的是当前这条线程）——
但你会看到名字变了，那不是 bug。

## 怎么区分「红灯点击」和「绿灯点击」

| 灯态 | 点灯珠的效果 | 是否破坏性 |
|---|---|---|
| 🔴 红 | 跳到等待你的那个窗口 | 否，随时可再点 |
| 🟢 绿 | 确认，绿灯熄灭 | **是**，会清掉告警 |
| 🟡 黄 / ⚫ 暗 | 无 | — |

**「忽略会话」不在这个表里**——它只在右键菜单，点灯珠永远碰不到它。

点外壳、点灭掉的灯珠都**没有反应**——这是刻意的，防止鼠标扫过时误触销毁告警。

如果绿灯在你没点的情况下自己灭了，那是 bug。设 `AI_TRAFFIC_LIGHT_DEBUG=1`
重启悬浮窗，状态文件和 `%LOCALAPPDATA%\ai-traffic-light\debug.log` 会记下是谁干的
（状态文件里的 `acked_by` 字段）。
