# 手工验收清单

自动化能覆盖的部分已经覆盖了（事件映射、聚合、点击判定、窗口跳转、忽略会话）。
剩下这些**必须人来判断**——下面每一条都写清了「怎么做」和「什么算通过」。

## 准备

1. 悬浮窗在跑：`.venv\Scripts\pythonw.exe src\main.py`
2. **开第二个 VSCode 窗口，打开另一个项目**（`文件 > 打开文件夹`，
   或 `Ctrl+K Ctrl+O`）。
   第 3 条测试需要两个窗口——只有一个窗口时「跳到那个窗口」无从谈起，
   这正是第一次测试失败的原因。

> 想手动摆出任意灯态来配合测试，用
> `python tools/simulate.py red|yellow|green|dark`，
> 测跳转用 `python tools/simulate.py redat "<项目目录>"`，
> 完事 `python tools/simulate.py clear`。

## 1. 悬停提示

**准备一条带标题的会话**：对任一项目派一次活。那句提问就是标题——只由
**第一条**指令决定，之后再说多少句都不会改。想验"同项目两行不一样"，
就在同一个项目里再开一个会话、派一句不同的话。

**怎么做**：鼠标移到灯上，停住。**不要点击。**

**通过**：
- 浮出一个**深色**圆角提示框（近黑底、浅灰字），不是系统默认的浅色框
- 一行一个会话：左边 `项目 · 指令`，右边是**带色**的状态词，右边缘**对齐**
- 颜色跟灯一致：红态红字、绿态绿字、黄态黄字
- 有原因时是**中文**（不是 `Claude needs your permission to use ...` 这种英文长句）
- 红灯底部有 `单击跳到等待中的窗口`；绿灯底部有 `单击确认，绿灯熄灭`
- 同项目开了两个会话时，两行的名字**不一样**
- 只列非暗态会话；超过 6 个时最后一行是 `…还有 N 个`
- **鼠标停住不动 5 秒，提示框不闪烁、不重绘、不跳位** ← 本次修的就是这个
- 鼠标移开再移回来，内容与当前灯态一致（不是上一次的残留）
- 顺带看一眼：右键菜单和「安装 hook」对话框外观没变

**不通过**：
- 什么都不弹，或弹出来只有「AI 状态灯」
- 提示里出现英文原文（原因映射没生效——多半是 hook 没重装，见 README 安装一节；
  会话名变成 `#a3f20000` 这种也是同一个原因）
- 同项目的两个会话看起来**逐字相同**
- 提示框是浅色的（`QToolTip` 样式表没生效）
- 鼠标停住时提示框持续闪烁或重绘
- 提示内容与灯色对不上（灯是绿的、提示说等待）

## 2. 拖动与位置记忆

**怎么做**：
1. 按住灯的外壳（圆角深色区域，任意位置）拖到屏幕另一个角
2. 右键 → 退出
3. 重新启动 `.venv\Scripts\pythonw.exe src\main.py`

**通过**：
- 拖动跟手，不卡顿、不跳变
- 重启后灯**还在你拖到的新位置**，没有回到默认位置

**额外一条**：故意**按住灯珠拖动**（不是外壳），松手后灯应该只是移动了，
**不应该被"确认"掉**（绿灯不该熄灭）。这验证的是 6px 移动阈值。

**不通过**：
- 拖不动
- 重启后回到默认位置（位置没存上）
- 拖到别的显示器后消失或跑到屏幕外（应该会被拉回可见区域）

## 3. 点击跳转（设计重头）

**前提**：两个 VSCode 窗口，各开一个项目。

**怎么做**：
1. 造一盏指向「另一个项目」的红灯：
   ```bash
   python tools/simulate.py redat "<另一个项目的目录>"
   ```
2. 点一下你的 VSCode，让它处于前台
3. 点一下灯的**红色灯珠**（不是外壳）

**通过**：VSCode 切到了那个项目的窗口——就是 `redat` 指定的那个。

**自动判定**（不用肉眼）：
```bash
python tools/test_jump.py "<另一个项目的目录>"
```
它会读前台窗口标题，执行跳转，再读一次，直接告诉你是通过还是失败。
注意它会真的抢一次焦点。

**不通过**：
- 点了没反应
- 切到了错误的窗口
- 新开了一个窗口而不是复用已有的（说明 `code -r` 没匹配上工作区）

> `code` 必须在 PATH 里。装 VSCode 时勾了「添加到 PATH」才有。
> 用 `python tools/test_jump.py list` 能看到当前所有 VSCode 窗口标题，
> 排查"到底切到哪儿去了"很有用。

## 4. 忽略会话（右键）

**为什么有这个**：红态唯一的自动出口是"同一个会话的下一个事件"。一个被丢下的会话
（窗口开着、`claude.exe` 还活着）永远不会有下一个事件，僵尸清理也够不着它——于是
红灯永远闪，并把别的会话的绿/黄一起盖住。右键忽略就是那个人肉出口。

**怎么做**：
1. 造一盏红灯：`python tools/simulate.py redat "<另一个项目目录>"`
2. 再键出第二个会话（可选，用来验证"只影响那一个"）：
   `python tools/simulate.py yellow`
3. 在灯上**右键 → 忽略会话**，点那一项

**通过**：
- 被忽略的会话从 `%LOCALAPPDATA%\ai-traffic-light\sessions` 里消失
- **只有它消失**——其他 `*.json` 还在，内容也没变
- 红灯**立刻**灭（不是 250ms 后），灯回落到那个会话该有的颜色
- 到那个 Claude Code 会话里**再派一次活**，它自动复活成黄；再卡住授权照样变红
- `debug.log` 里有一行 `IGNORE <session_id> by=menu`
  （**只有以 `AI_TRAFFIC_LIGHT_DEBUG=1` 启动悬浮窗才有这一行**——见 README 的排查一节）

**不通过**：
- 点了没反应
- **别的会话也一起消失了**——这是最严重的一条，等于凭空抹掉一次告警
- 被忽略的会话在**没有任何动静**的情况下自己回来了
  （那是 `hook_writer` 里 `path.exists()` 与原子写之间的窄竞态，值得记录下来）

**一条反直觉的、不算故障的**：如果你点了一个**没有 `●` 前缀**的红灯，灯可能仍是红的——
那是**另一个**红灯在占位。先看菜单里谁带 `●`，那才是正在点灯的那个。
同理，一次右键只能忽略一个会话（Qt 在条目触发后就关掉了整条菜单），三个卡死就右键三次。

**另一条不是故障的**：忽略一个**绿**的会话，等于一次"没留下 `acked_by` 记录的确认"。
绿灯本来就要你点确认，这里只是换了种方式让它消失，不会记录在案。

**还有一条不是故障的（标题相关）**：忽略一个会话，等于连它的标题一起删了。
那个会话下次真有动静复活时，标题会变成**让它复活的那条指令**，不是原来那条。
对被丢下又回来的会话来说这反而更准（它描述的是当前这条线程）——
但你会看到名字变了，那不是 bug。

## 怎么区分「红灯点击」和「绿灯点击」

| 灯态 | 点灯珠的效果 | 是否破坏性 |
|---|---|---|
| 🔴 红 | 跳到等待你的那个窗口 | 否，随时可再点 |
| 🟢 绿 | 确认，绿灯熄灭 | **是**，会清掉告警 |
| 🟡 黄 / ⚫ 暗 | 无 | — |

**「忽略会话」不在这个表里**——它只在右键菜单，点灯珠永远碰不到它。

点外壳、点灭掉的灯珠都**没有反应**——这是刻意的，防止鼠标扫过时误触销毁告警。

如果绿灯在你没点的情况下自己灭了，那是 bug。设 `AI_TRAFFIC_LIGHT_DEBUG=1`
重启悬浮窗，状态文件和 `%LOCALAPPDATA%\ai-traffic-light\debug.log` 会记下是谁干的
（状态文件里的 `acked_by` 字段）。
